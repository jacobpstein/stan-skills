# Simulation-Based Calibration Checking

Source: *Bayesian Workflow* ch. 14; Talts et al. (2018); Modrák et al. (2025); Säilynoja,
Bürkner & Vehtari (2022).

The name is "simulation-based calibration **checking**": it checks, it does not calibrate.

## What it tests

If the prior-predictive generator and the posterior code define the same model, and the sampler
is correct, then the rank of a prior draw among posterior draws from data generated by that prior
draw is **uniform**. Two things can break that:

1. The inference algorithm is incoherent (implementation error, non-convergence, an approximation
   that distorts the posterior).
2. The generator and the implemented posterior density are not the same model (a transcription
   error in the priors, a wrong link, an indexing bug).

Writing the prior twice, once as a generator and once in the model block, and checking they agree,
is the point.

## The procedure

1. Draw `theta_s ~ p(theta)`, **exactly** from the prior, for `s = 1..S`.
2. Simulate `y_s ~ p(y | theta_s)`.
3. Fit the model to each `y_s`, keeping `M` approximately independent posterior draws. Thin
   correlated MCMC draws. `M = 99` or `M = 999` keeps the rank histogram bins even.
4. Choose test quantities `T(theta, y)`: the parameters themselves, plus functions of parameters
   and data (log-likelihood, a prediction, a contrast).
5. For each `s`, compute the rank of `T(theta_s, y_s)` among the `M` posterior values.
6. Break ties uniformly at random for discrete quantities.
7. The `S` ranks should be uniform on `{0, ..., M}` for every test quantity.

Equivalently: posterior intervals of any width `p` contain the truth in proportion `p` of
simulations.

## Python implementation

```python
import numpy as np
from cmdstanpy import CmdStanModel

gen  = CmdStanModel(stan_file="stan/model_prior_sim.stan")
post = CmdStanModel(stan_file="stan/model.stan")

S, M, THIN, CHAINS = 200, 99, 10, 4
params = ["alpha", "beta", "sigma"]
ranks = {p: [] for p in params}
diagnostics = []

for s in range(S):
    sim = gen.sample(data={"N": N, "x": x}, fixed_param=True,
                     chains=1, iter_sampling=1, seed=1000 + s, show_progress=False)
    truth = {p: float(sim.stan_variable(p)[0]) for p in params}
    y = sim.stan_variable("y_sim")[0]

    fit = post.sample(data={"N": N, "x": x, "y": y, "prior_only": 0},
                      chains=CHAINS, iter_sampling=M * THIN // CHAINS, thin=THIN,
                      seed=2000 + s, show_progress=False)
    diagnostics.append(dict(div=int(fit.divergences.sum()),
                            rhat=float(fit.summary()["R_hat"].max())))
    for p in params:
        draws = fit.stan_variable(p).ravel()
        ranks[p].append(int((draws < truth[p]).sum()))

ranks = {p: np.array(v) for p, v in ranks.items()}
```

Discard or flag simulations whose fit failed to converge before interpreting the ranks; a
non-uniform histogram caused by divergent fits is a computation problem, not a model-code problem,
and you want to know which.

Plot the ECDF difference with simultaneous bands:

```python
import arviz as az
pit = {p: (v + np.random.uniform(size=v.size)) / (M + 1) for p, v in ranks.items()}
dt = az.from_dict({"prior_sbc": {k: val[None, :] for k, val in pit.items()}})
az.plot_ecdf_pit(dt, group="prior_sbc")
```

## R implementation with the SBC package

```r
library(SBC); library(cmdstanr)

simulate_one <- function(N, x) {
  alpha <- rnorm(1, 0, 2.5); beta <- rnorm(1, 0, 1); sigma <- abs(rnorm(1, 0, 1))
  list(variables = list(alpha = alpha, beta = beta, sigma = sigma),
       generated = list(N = N, x = x, y = rnorm(N, alpha + beta * x, sigma), prior_only = 0))
}

gen <- SBC_generator_function(simulate_one, N = 100, x = x)
ds  <- generate_datasets(gen, n_sims = 200)
bkd <- SBC_backend_cmdstan_sample(mod, chains = 4, iter_sampling = 1000, thin = 10)
res <- compute_SBC(ds, bkd)

plot_rank_hist(res)
plot_ecdf_diff(res)
res$stats          # per-variable rank statistics and diagnostics
```

`SBC` caches results, parallelizes the fits, and records convergence diagnostics per simulation,
which is worth the dependency for a real SBC run.

## Reading the diagnostics

**Rank histogram** with a 95% band for uniformity:

| Shape | Diagnosis |
|---|---|
| Flat inside the band | calibrated |
| Piled at low ranks (decreasing) | posterior systematically **over**estimates the parameter |
| Piled at high ranks (increasing) | posterior systematically **under**estimates |
| U shape | posterior too **narrow**, overconfident |
| Inverted U (∩) | posterior too **wide** |
| Flat plus a spike at one end | a subset of fits produce extreme estimates; check convergence |

**ECDF-difference plot** (preferred): observed rank ECDF minus uniform, with an exact
simultaneous 95% band. The same problems appear as a positive hump, a negative trough, an S curve
(too certain), a mirrored S (too uncertain), or a drift at one end.

**The gamma statistic** ranks test quantities by how extreme their worst ECDF point is under
uniformity:

```
gamma = 2 * min_i [ min( Binomial(R_i | S, z_i), 1 - Binomial(R_i - 1 | S, z_i) ) ]
```

with `z_i = i / (M + 1)` the expected proportion below rank `i` and `R_i` the observed count.
Order your test quantities by `gamma` and inspect the worst ones manually. Kolmogorov-Smirnov and
chi-squared tests have poor sensitivity here; use `gamma` or the ECDF bands.

## Wide priors make SBC correct but useless

Weakly informative priors that barely affect the posterior can still be extreme when you simulate
*from* them: `a, b ~ normal(0, 100)` in a logistic regression generates datasets that are all
zeros or all ones, and an air-pollution model can generate concentrations "denser than a black
hole". SBC is then mathematically valid but irrelevant to the parameter region you care about,
and the extreme datasets can make a perfectly good algorithm fail.

Two fixes:

1. **Tighter priors**, possibly joint rather than independent.
2. **Rejection sampling on the datasets**: discard simulated datasets failing a criterion and
   regenerate. As long as the criterion depends **only on the data** and not on the latent
   parameters, the posterior is unchanged and SBC stays valid.

```python
def acceptable(y):
    return y.std() > 1e-6 and y.max() < 1e6 and 0 < y.mean() < 1e4
```

## Posterior SBC

After you have real data, check calibration only in the region the posterior actually occupies:
use the fitted posterior as the "prior", simulate new data from it, combine with the original
data, and rerun the same inference. This cannot detect a mismatch between the generator and the
density (the same code is used both times), but it does detect **incoherence of the inference
algorithm with respect to Bayesian updating**: implementation mistakes, incomplete sampling, and
the bias behind a couple of stray divergences. It is also the way to check an amortized or
approximate inference method in the region that matters.

## When you cannot afford 1000 replications

Run 20. A few extreme ranks (0 or M) appearing repeatedly already indicate a problem. Start with
SBC on a smaller submodel, or on a reduced dataset size, which is faster and usually surfaces the
same code bugs. Some checking beats none.

## Interpreting a clean result

Finite `S` limits the miscalibration you can detect, chance misses happen, and miscalibrations in
different regions can cancel in a marginal. Add derived test quantities (log-likelihood, a
predictive quantity, a contrast of interest) rather than relying on the marginals of the raw
parameters alone.

## SBC as a software test

- Testing a **new inference algorithm**: run it against models whose posteriors are known to be
  recoverable. Bad calibration means a bug in the algorithm or in the target density.
- Testing a **new model implementation**: keep the prior-predictive generator in a separate file
  from the posterior program. SBC then verifies the two define the same model, which no amount of
  reading the code reliably does.
